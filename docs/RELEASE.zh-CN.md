# 固件发行

[English](RELEASE.md)

Release 标题只使用标签，采用 `vA.B.C-rN`，例如 `v1.2.1-r1`。正文采用 `docs/releases/<tag>.md` 中的简短英文更新说明，并链接 `<tag>.zh-CN.md` 简体中文版。

附件只上传刷机镜像和签名系统 OTA 包，两者均使用 XZ 压缩：

```text
armhpc_<版本>_<设备型号>_<系统代号>_<内核版本>_<文件系统>_<编译日期>.img.xz
armhpc-ota_<版本>_<设备型号>_<系统代号>_<内核版本>_<文件系统>_<编译日期>.tar.xz
```

编译日期使用实际 `YYYYMMDD`，内核版本不带软件包后缀。签名清单、载荷哈希、许可、构建来源及对应源码材料放入 OTA 包或镜像；校验文件、报告、源码归档和清单不作为额外附件上传。GitHub 的 Source code 链接由平台生成。

发布前校验两个本地文件和上传后的哈希，再删除旧附件。同名文件内容不同不得覆盖，需使用新版本。

源码检查和导出使用 `image-framework.py check-source` 与 `prepare-source-release`。固件记录包含精确源码 commit 及签名序号，并检查内核／模块／DTB／raw initramfs 配套、永久引导组件、许可及对应源码、身份清理和分区边界。二进制、私钥、凭据、MiniLoader 和节点备份保存在 Git 外。

每次发布通过 --manifest 提供全部机型的完整清单，包含 tag、file、size、sha256，以及每个 IMG 的已审查再分发依据。v1.2.0 的计划清单为 OECT 和 OESP 各一个 IMG.XZ、一个 OTA TAR.XZ，共四项。不得逐机型更新附件；草稿通过 --release-id 定位。


## 版本编号

采用 `vA.B.C-rN`，`r` 为小写，修订号为正整数。两个仓库各自管理版本：基础版本每次递增一个修订版本，或递增一个次版本并将修订版本归零，或递增一个主版本并将次版本和修订版本归零。例如 `1.2.3` 可进入 `1.2.4`、`1.3.0` 或 `2.0.0`。同一基础版本下修订号递增，允许直接发布 `r1`、`r3`、`r9`。已有不带修订号的数字版本继续兼容。

Release 标题与 tag 一致，附件文件名包含修订号。兼容性仍按数字基础版本、明确能力和签名清单要求校验；固件签名序号独立递增。正式发布前先检查本仓库已公开版本顺序，再执行上传或元数据修改。同名已发布文件保持原字节。
